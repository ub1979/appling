# Site blueprints

Section order and the job of each section, per site type. Adapt the count
to the build profile (a Personal site may be one page with 4–6 sections);
keep the order of the jobs.

## Contents
- AI product
- Software product (SaaS)
- Landing page (one offer)
- New company
- Developer site
- Shared parts (navigation, footer, pricing, FAQ)

## AI product

The visitor's questions: what does it do, does it actually work, can I
trust it with my data, what does it cost.

1. **Hero** — outcome headline ("Answers from your docs in seconds", not
   "AI-powered knowledge platform"), subhead naming who it is for, primary
   call to action, and a *live-looking* demo: a real prompt → real answer
   in the product UI, typed in on load. No glowing brains, robots or
   abstract neural art as the hero.
2. **Proof strip** — real customer logos, a usage number, or a press
   quote. Placeholder when none exists.
3. **How it works** — three steps (connect → ask → act) with a product
   screen for each.
4. **Use cases** — 3–6 cards, each a concrete job with a before/after.
5. **Show the model at work** — a comparison or worked example: input,
   output, sources cited. Honest about limits.
6. **Trust and data** — where data goes, retention, security standards the
   owner really meets, human review options.
7. **Integrations** — the tools it plugs into (real logos only if they are
   real integrations).
8. **Pricing** — see shared parts.
9. **FAQ** — accuracy, privacy, pricing, setup time.
10. **Final call to action** — repeat the headline promise and the button.

Look: confident and precise rather than "futuristic". One accent colour,
a lot of whitespace, product UI as the main picture. Dark themes are fine
when the product UI is dark; avoid the purple-to-blue gradient default.

## Software product (SaaS)

1. **Hero** — headline (outcome), subhead (who + how), two calls to action
   (start / book a demo), a large product screenshot in browser chrome,
   slightly angled or cropped to the most impressive view.
2. **Logo strip / proof**.
3. **Problem → outcome** — the pain in the visitor's words, then the
   result with the product.
4. **Feature sections** — 3–4 alternating rows: headline (benefit), two
   lines (mechanism), one focused screenshot or short UI loop.
5. **Bento grid** — 5–7 secondary capabilities in cards of mixed size.
6. **Testimonial** — one real, attributed quote with photo and role.
7. **Pricing**, **FAQ**, **final call to action**, **footer**.

Look: crisp UI screenshots carry the page; cards with 1 px borders or soft
elevation, consistent radius, generous section spacing (96–160 px desktop).

## Landing page (one offer)

One page, one goal, one call to action repeated. Everything that does not
move the visitor toward it is removed (no full navigation; logo + button).

1. Hero — offer headline, the single call to action, the key picture.
2. The problem it solves (short).
3. What you get — 3–5 benefits with icons or small pictures.
4. Proof — testimonial, result, guarantee the owner offers.
5. How it works — 3 steps.
6. Objections — FAQ.
7. Final call to action with urgency only if it is real (a real deadline).

Forms: as few fields as possible (email first), clear success state.

## New company

The visitor wants to know who you are, what you do, and whether you are
credible.

1. **Hero** — a clear positioning line (what + for whom), a strong
   photograph or designed visual, one call to action (contact / see work).
2. **What we do** — 3–4 services or products, each linking deeper.
3. **Why us** — the approach or principles; specific, not "innovative
   solutions".
4. **Work / products / case studies** — real when they exist; otherwise
   describe the capability without inventing clients.
5. **Team** — real people, real roles (or founders only).
6. **Story / mission** — short.
7. **Contact** — form, email, location if relevant.

Pages for a Reusable/Production profile: Home, About, Services/Product,
Contact, plus Careers or Blog only when the owner has content.

Look: a confident type lockup for the name, a restrained palette taken from
the brand (or proposed as a starting brand), photography over icons.

## Developer site

For APIs, SDKs, open-source projects and dev tools.

1. **Hero** — what it does in one line, an install command with a copy
   button, a code sample that works, links to docs and the repository.
2. **Code-first features** — each feature as a short code block and its
   output, side by side.
3. **Quick start** — 3 steps, copy-pastable.
4. **Ecosystem** — languages, frameworks, integrations.
5. **Community / proof** — repository stars, users, contributors (real).
6. **Docs entry points** — guides, API reference, examples.

Look: a monospace accent face for code, an editor-like palette (from a real
IDE theme the owner likes), syntax highlighting that passes contrast,
dark and light themes both tested.

## Shared parts

- **Navigation**: logo left, 4–6 links, one primary button right; on phones
  a menu button with a full-height panel, trapped focus, Escape closes it.
- **Pricing**: 2–3 tiers, the recommended one highlighted, monthly/yearly
  toggle only when both exist, a feature comparison under the cards, prices
  the owner confirmed.
- **FAQ**: `<details>` elements, 5–8 real questions.
- **Footer**: product links, company links, legal (privacy, terms — the
  owner supplies the text), social links that exist, copyright year.
